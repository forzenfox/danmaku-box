## 1. 需求背景

### 1.1 需求来源

产品发起人提出：当前插件只能在右侧聊天区右键收藏弹幕，希望支持在**直播画面（视频区）水平飘过的飘屏弹幕**上直接右键唤出收藏入口，体验对标 DouyuEx 的"右键弹幕"感知。

### 1.2 用户痛点

**视线焦点处的好弹幕，收藏要"拐弯"。** 用户观看直播时视线集中在视频画面，飘屏弹幕从画面上划过时产生的收藏冲动最强、时效最短（弹幕约 120px/s 横移，数秒后离场[实测支持：2026-09-17]）。当前唯一路径是把视线和鼠标移到右侧聊天区、在滚动列表中找到同一条弹幕再右键——多数情况下弹幕已上翻，收藏意愿在中途流失。[PM 判断]

### 1.3 现状与可行性裁决

**现状：飘屏分支"看起来支持、实际不可用"。** 代码层已有飘屏分支（选择器、暂停、坐标兜底），但现场实测证明该分支从未在真实飘屏场景下工作过，存在 3 处缺陷：

| # | 缺陷 | 实测依据 | 用户可感知后果 |
|---|------|---------|--------------|
| 1 | 选择器命中错层：`[class*="danmu-"]` 命中的是飘屏**层容器**而非弹幕项 | 容器 `textContent` 实测为 12 条弹幕文本拼接 | 即使命中，收藏内容是全部弹幕的拼接串 |
| 2 | 暂停机制失效：注入 `animation-play-state` 对飘屏位移无效 | 位移由 Web Animations API 驱动（`animationName: "none"`） | 右键后弹幕继续滚动，无视觉反馈，菜单追不上目标 |
| 3 | 移动目标命中无兜底：仅靠右键瞬间的坐标命中 | 弹幕约 120px/s 移动，右键时序内目标已位移 | 真实右键可能落空（命中下层视频容器），菜单不出或出错对象 |

**可行性裁决：技术可行。** 命中、文本提取、暂停/恢复、事件接管四条机制链路全部通过现场实测验证；改动集中在斗鱼适配器层与右键控制器，通用层（弹幕库、分组、收藏链路）零改动。[实测支持：2026-09-17 可行性报告第 01、03 节]

**对标澄清：DouyuEx 没有视频区右键功能。** 对 DouyuEx 脚本全量逆向核查确认：其"弹幕右键信息扩展"是被动的聊天区原生面板增强（且不含收藏按钮），不覆盖视频区飘屏弹幕。本需求以**自建右键菜单**为唯一技术路线，DouyuEx 的可借鉴项在工程策略层（特征探测选择器、按需发现），无现成实现可抄。[调研支持：可行性报告第 05 节]

## 2. 需求目标与范围

### 2.1 目标

| # | 目标 | 衡量方式 |
|---|------|---------|
| GV1 | 用户在飘屏弹幕上右键，被点弹幕冻结并弹出「藏+」菜单，全程 ≤ 100ms | 操作走查 + 性能验收 |
| GV2 | 收藏写入的内容 100% 为单条弹幕文本（非多条拼接、非层容器内容） | 自动化契约测试 |
| GV3 | 菜单以任意方式关闭后，被冻结弹幕 100% 恢复运动，无永久卡死 | 人工走查（含池化复用场景） |
| GV4 | 飘屏右键与聊天区右键的菜单结构、收藏链路完全一致，用户无需二次学习 | 交互走查 |
| GV5 | 视频全屏模式下右键收藏可用 | 人工走查 |

### 2.2 范围

**做**：飘屏弹幕右键命中判定（含移动目标兜底）、单条冻结与恢复、复用「藏+」右键菜单、全屏宿主适配、空场景与结构变更的降级容错、设置开关语义统一。

**不做**：
- 抖音飘屏路径（二期随主 PRD Q5 登录态验证另行裁决）；
- 飘屏弹幕的其他增强（弹幕屏蔽、样式调整、举报等），本功能只做"右键收藏 + 复制"；
- 原生右键面板的扩展或注入（实测视频区不存在原生面板，且站点已屏蔽原生菜单，自建菜单属"填补空白"）。

### 2.3 产品原则（继承与补充）

- **融入而非改造**（继承主 PRD 2.3）：视频区右键原本无任何菜单（站点已屏蔽原生菜单[实测支持]），插件菜单为填补空白，不抢占任何既有交互。
- **最小冻结**（本 PRD 新增）：冻结范围仅限被右键的单条弹幕，不干扰画面内其他弹幕的运动与展示。
- **实时判定优先**（继承项目工程经验）：命中判定以事件发生时刻的实时校验为准，历史采样仅作兜底且须通过一致性校验，不依赖延迟与重试。

## 3. 用户与使用场景

### 3.1 场景（按优先级）

**场景 V1：视线不离开画面完成收藏（最高优先级）**
主播整活时一句梗弹幕飘过画面，用户直接在该条弹幕上右键 → 弹幕原地冻结、菜单弹出 → 点分组完成收藏。全程视线与鼠标都在视频区内，不打断观看。

**场景 V2：全屏观看时随手收藏**
用户以视频全屏模式观看，好弹幕飘过，右键 → 菜单在全屏内正常出现 → 收藏后弹幕恢复滚动，继续全屏观看。

**场景 V3：活动应援快速入库**
冲榜活动刷屏期（弹幕密度高），用户在密集飘屏中右键目标口号弹幕 → 即使右键瞬间弹幕仍在高速移动，菜单仍准确锁定该条 → 收藏到"应援"分组。

### 3.2 用户故事

- 作为一名活动型观众，我希望直接在画面上飘过的弹幕上右键收藏，这样不用把视线挪去聊天区翻找。
- 作为一名整活型观众，我希望右键后那条弹幕停住不动，这样我能确认收藏的就是这一条。
- 作为一名全屏观看的用户，我希望全屏时右键菜单照样能用，这样不用退出全屏再收藏。
- 作为一名用户，我希望关掉右键收藏开关后视频区右键恢复原样，这样插件完全不打扰我。

## 4. 术语表（增量，基础术语见主 PRD 第 5 章）

| 术语 | 定义 |
|------|------|
| 飘屏层容器 | 覆盖视频区的弹幕层元素，`pointer-events:none`，永不成为鼠标事件目标 |
| 弹幕项 | 飘屏中单条弹幕的 DOM 元素，`pointer-events:auto`，携带 `data-comment-uuid` 唯一标识 |
| 冻结 / 恢复 | 暂停 / 继续单条飘屏弹幕的横移动画 |
| WAAPI | Web Animations API，飘屏位移的实际驱动机制（非 CSS animation） |
| 对象池复用 | 站点回收已离场弹幕的 DOM 元素并复用给新弹幕，元素身份（uuid、文本）会更换 |
| hover 采样缓存 | 右键发生前对指针轨迹下弹幕项的短时采样记录，用于移动目标的命中兜底 |
| 三级命中 | 右键目标判定的优先级链：事件目标 → hover 采样缓存 → 坐标叠层反查 |

### 5.1 FR-V01 飘屏右键命中

#### 原型示意

```
┌─────────────────────────── 视频直播画面 ───────────────────────────┐
│                                                                     │
│   ════════ 飘屏弹幕 A（照常滚动，不受影响）═════════════→           │
│                                                                     │
│        ╔══════════════╗                                            │
│        ║ 666冲冲冲 ❄  ║  ← 被右键的弹幕：原地冻结                  │
│        ╚═════╤════════╝                                            │
│              │  ┌──────────────────────┐                           │
│              └─▶│ 收藏到 ▸  应援口号    │  ← 「藏+」菜单            │
│                 │            整活文案  │    （跟随指针·避让视口）     │
│                 │            默认收藏  │                           │
│                 ├──────────────────────┤                           │
│                 │  ✚ 收藏到新分组       │                           │
│                 │  ⧉ 复制弹幕文本       │                           │
│                 └──────────────────────┘                           │
│                                                                     │
│   ════════ 飘屏弹幕 B（照常滚动，不受影响）═════════════→           │
└─────────────────────────────────────────────────────────────────────┘
```

#### 业务逻辑

用户在飘屏弹幕上按下右键时，插件按**三级命中链**判定目标弹幕项，判定成功后冻结该条弹幕（FR-V03）并弹出「藏+」菜单（FR-V04）。三级命中的必要性来自实测：弹幕以约 120px/s 横移，从指针按下到 `contextmenu` 触发之间目标已位移，单靠事件目标或单次坐标查询都会落空。[实测支持：2026-09-17]

| 优先级 | 判定来源 | 说明 |
|-------|---------|------|
| ① 事件目标 | `contextmenu` 的 `target` 向上追溯弹幕项 | 静止或慢速弹幕的最快路径 |
| ② hover 采样缓存 | 右键前 ≤300ms 内指针轨迹下的弹幕项记录 | 兜底右键时序内目标的位移；须通过三重校验 |
| ③ 坐标叠层反查 | 右键坐标处 `elementsFromPoint` 的命中链 | 最后兜底；仅采纳首位为弹幕项的结果 |

**三重校验**（②③ 采样的采用前提，防对象池复用误判[实测支持：同元素 1.5s 内 uuid 与文本均更换]）：

| 校验项 | 规则 |
|-------|------|
| 连接性 | 元素 `isConnected === true`（未脱离文档） |
| 身份一致 | `data-comment-uuid` 与采样时记录一致 |
| 距离阈值 | 采样坐标与右键坐标的距离在阈值内（工程默认 40px，允许微调） |

三级全部未命中时，本次右键不响应（不出菜单、不拦截），原生行为不受影响。

#### 交互逻辑

| 用户动作 | 系统响应 |
|---------|---------|
| 右键飘屏弹幕（命中） | 冻结该条弹幕，弹出「藏+」菜单，指针操作与聊天区右键一致 |
| 右键飘屏弹幕（三级均未命中） | 无菜单、无拦截，本次右键等同站点缺省行为（无菜单） |
| 右键视频区空白处（非弹幕） | 无菜单、无拦截 |
| 指针掠过弹幕（未右键） | 无任何可见反馈（hover 采样为静默记录，不改变弹幕外观） |

#### 字段规则

| 参数 | 值 | 说明 |
|------|----|----|
| hover 采样窗口 | ≤ 300ms | 超时采样不参与命中判定 [工程默认，允许走查微调] |
| 采样方式 | `mousemove` 捕获 + 节流 | 事件驱动、低频，无可感知性能影响 |
| 距离阈值 | 40px | 采样坐标与右键坐标的容差 [工程默认，允许走查微调] |

#### 边界与异常

- **高密度刷屏**：多条件弹幕在指针下方交叠时，以事件目标/hit 链首位为准（视觉最上层），不弹选择列表。
- **弹幕已滚出视野**：右键时目标已离场（②缓存命中但元素已复用）→ 三重校验拦截 → 按未命中处理，不出菜单。
- **命中后弹幕被回收**：命中判定与文本提取在同一时刻同步完成，收藏数据不因后续元素复用而变化；冻结与恢复对已复用元素安全跳过（见 FR-V03 边界）。

### 5.2 FR-V02 弹幕项定位与文本提取

#### 业务逻辑

适配器以**特征探测**定位飘屏元素，不硬编码哈希类名；文本提取自弹幕项内的文本节点，保证单条纯度。

| 目标 | 定位方式 | 实测依据 |
|------|---------|---------|
| 弹幕项 | `[class*="danmuItem"]`（命中元素本身，非父级容器） | 弹幕项 `pointer-events:auto`，携带 `data-comment-uuid`；层容器为 `pointer-events:none` 永不成为事件目标 |
| 文本节点 | 弹幕项内 `[class*="textWrap"]` | 文本节点内容为纯弹幕文本，不含昵称/粉丝牌结构 |

**禁止**使用 `[class*="danmu"]` / `[class*="danmu-"]` 类宽匹配——实测会误命中层容器及 `.danmudiv-*`、`.danmuAuthor-*` 等无关的原生面板元素。[实测支持：可行性报告第 04 节缺陷 1/2]

#### 交互逻辑

| 场景 | 提取结果 |
|------|---------|
| 普通文本弹幕 | 弹幕项 → 文本节点内容（trim 后） |
| 富内容弹幕（含表情/图片元素） | 只提取纯文本部分，`hasRichContent=true`，toast 注明"已忽略表情/图片"（继承 FR-01 规则） |
| 空文本弹幕（纯表情） | 文本为空："复制弹幕文本"置灰，收藏保存为空文本条目（继承 FR-01 规则） |

#### 字段规则

飘屏收藏写入的数据模型与聊天区完全一致（content / platform / room / created_at），无新增字段。`data-comment-uuid` 仅作运行时命中校验标识，**不进入收藏数据**（飘屏弹幕无昵称等社交信息，与聊天区收藏的字段口径一致）。

### 5.3 FR-V03 弹幕冻结与恢复

#### 业务逻辑

右键命中后，插件通过 Web Animations API 冻结**被点的那一条**弹幕的横移动画；菜单关闭后恢复。**只冻结单条，画面内其余弹幕照常滚动。**

> **产品行为修正说明**（对主 PRD FR-01）：主 PRD 原定"暂停全部飘屏运动"。实测后修正为单条冻结，理由：① 飘屏位移由 WAAPI 驱动，标准 API 支持单条精确 `pause()/play()`，无副作用[实测支持]；② 全部暂停反而制造体验割裂——对象池持续复用元素，暂停瞬间后新入场弹幕仍在滚动，画面呈现"半静半动"的混乱态；③ 用户意图只与被点的那条弹幕相关，最小冻结符合"融入而非改造"原则。[PM 判断 + 实测支持]

#### 交互逻辑

| 时机 | 系统行为 |
|------|---------|
| 右键命中（菜单弹出前） | 冻结目标弹幕动画 |
| 菜单关闭（点击收藏/Esc/点击菜单外） | 恢复目标弹幕动画，菜单关闭与恢复同帧完成 |
| 收藏完成 | 恢复动画 + toast"已收藏到「分组名」"（2s 消失，继承 FR-01） |

#### 边界与异常

- **动画已结束/已取消**：冻结/恢复调用做静默容错，不抛错、不影响菜单与收藏流程（弹幕已离场时收藏仍有效，见 FR-V01 边界）。
- **元素被池化复用**：恢复操作持有的是 `Animation` 对象引用而非仅元素引用；恢复前校验元素连接性与 uuid，不一致则跳过（宁可漏恢复一条已复用元素，不可错恢复别人的动画）。
- **动画引用泄漏**：冻结记录使用弱引用结构（元素被回收后记录可被垃圾回收），不长期驻留内存。
- **连续右键多条弹幕**：同一时刻仅一个活动菜单；新右键命中时，先恢复上一条冻结弹幕再冻结新目标，不产生"孤儿冻结"。

### 5.4 FR-V04 收藏菜单交互（飘屏差异项）

#### 业务逻辑

飘屏右键弹出的是**同一个**「藏+」右键菜单组件：分组列表（最近使用排前）、收藏到新分组、复制弹幕文本，结构与聊天区右键完全一致（主 PRD FR-01 定义，本节只定义差异项）。收藏写入走既有消息链路，通用层零改动。

#### 交互逻辑（差异项）

| 用户动作 | 系统响应 |
|---------|---------|
| 菜单出现位置 | 跟随右键坐标右下方，自动避让视口边缘（视频区通常宽大，菜单允许覆盖部分画面） |
| 点击某分组 | 收藏写入 → 恢复弹幕 → 关闭菜单 → toast |
| 按 Esc / 点击菜单外 | 恢复弹幕 → 关闭菜单（无 toast） |
| 菜单开启期间，其余弹幕 | 照常滚动，不做任何干预 |

#### 边界与异常

- **超长弹幕预览**：菜单内预览超过 2 行截断，悬停看全文（继承 FR-01）。
- **弹幕密度极低**（画面仅 1~2 条飘屏）：行为无差异，正常命中与冻结。
- **直播结束/无飘屏层**：见 FR-V06 降级。

### 5.5 FR-V05 全屏与多场景适配

#### 业务逻辑

视频全屏（Fullscreen API）时，既有菜单宿主（挂 `documentElement`）不在全屏渲染树内，菜单不可见。插件监听 `fullscreenchange`：进入全屏时将菜单宿主迁入全屏元素内，退出时迁回原位置。菜单的弹出、避让、关闭逻辑在全屏内外保持一致。

> 该策略与「藏+」工具栏弹层"全屏即收起"的既有策略**并存不悖**：工具栏弹层属驻留型入口（全屏收起合理），右键菜单属瞬时型入口（用户主动唤出，必须就地可见）。[PM 判断]

#### 交互逻辑

| 场景 | 用户感知 |
|------|---------|
| 视频全屏下右键弹幕 | 菜单在全屏画面内正常出现，可完成收藏 |
| 全屏下按 Esc | 关闭菜单；退出全屏为浏览器默认行为（UA 对 Esc 的处理先于页面，无 Keyboard Lock API 时页面无法阻止），产品接受此限制；如需仅关菜单需 Keyboard Lock API，列为后续增强 |
| 退出全屏 | 宿主迁回文档，后续非全屏右键正常 |
| 网页全屏/影院模式 | 宿主仍在文档流内，无需迁移；菜单避让走查覆盖 |

#### 边界与异常

- **全屏切换瞬间右键**：迁移为同步监听，切换完成前的右键按当前渲染树判定，最坏情况为本次不响应，下次正常。
- **宿主迁移失败**：菜单不出现（等同未命中降级），不报错、不影响收藏库其他入口。

### 5.6 FR-V06 降级容错与设置开关

#### 业务逻辑

飘屏能力遵循主 PRD FR-06 两级降级原则的**局部缺失**档：飘屏路径定位失败（结构变更/Canvas 改版/无弹幕层）时静默跳过，不出菜单、不拦截右键、不报错；聊天区右键、弹幕库、回填等其余功能不受影响。

| 探测场景 | 判定 | 行为 |
|---------|------|------|
| 首屏无弹幕 / 直播结束（无飘屏元素） | 飘屏层不存在 | 静默：右键无菜单，站点缺省行为不变 |
| 哈希类名变更（`danmuItem-*` 失配） | 特征探测失败 | 静默降级；选择器集中配置便于热修 |
| 站点改版为 Canvas 渲染弹幕 | 飘屏 DOM 缺失 | 适配器探测降级（当前为 DOM 渲染，无改版迹象[实测支持]） |

#### 设置开关

| 项 | 规则 |
|----|------|
| 开关名称 | **弹幕右键收藏**（由"聊天区右键收藏"语义扩展，单一开关同时控制聊天区与视频区两处右键菜单） |
| 默认值 | 开启 |
| 关闭后 | 聊天区与视频区右键均不拦截、不出菜单，两处恢复站点缺省行为；弹幕库/回填不受影响 |
| 存量用户 | 既有开关状态与值原样继承，仅文案与作用范围更新 |

> 单一开关而非两处独立开关的理由：两处是同一功能（右键收藏）的两个入口，拆分会增加设置理解成本；视频区右键原本无菜单（站点已屏蔽），本功能为纯增量，误扰风险低。[PM 判断]

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 右键命中 → 冻结 → 菜单弹出 ≤ 100ms（沿用主 PRD）；冻结/恢复为单条 WAAPI 调用（毫秒级）；hover 采样为节流监听（事件驱动 + 低频），无可感知性能影响 |
| 稳定性 | 对象池复用、动画已结束、宿主迁移失败等异常均静默容错，不抛错、不阻塞页面；单一弹幕的冻结异常不拖垮菜单与收藏链路 |
| 兼容性 | `getAnimations()` 为标准 DOM API，作用于共享 DOM，扩展 isolated world 可正常操作（实现后首验，风险低[实测评估]） |
| 账号安全 | 本功能仅读取页面 DOM 与调用动画暂停 API，不触碰登录、发送等账号敏感行为 |
| 隐私 | hover 采样仅驻留内存（≤300ms 窗口），不落盘、不上报 |

## 7. 验收标准

### 7.1 自动化验收（契约测试，实现阶段 TDD 先行）

对应可行性报告 6.2 改动点清单，作为测试用例输入：

| # | 验收项 | 通过标准 |
|---|-------|---------|
| C1 | 弹幕项定位 | 给定飘屏 DOM 片段，命中弹幕项（非层容器） |
| C2 | 文本纯度 | 提取结果 = 文本节点内容（非容器拼接串） |
| C3 | 冻结机制 | 冻结调用 `getAnimations().pause()`（WAAPI）；无动画元素不抛错 |
| C4 | 池化竞态 | 元素 uuid 变化/脱离文档时，命中与恢复操作安全跳过 |
| C5 | 缓存时效 | 采样超时（>300ms）或 uuid 不一致 → 不采用该缓存 |
| C6 | 缓存兜底命中 | 事件目标未命中但缓存有效 → 正常出菜单 |
| C7 | 关闭恢复 | 菜单关闭 → 恢复动画被调用 |
| C8 | 签名兼容 | 适配器 `pauseDanmu` 无参调用保持既有语义（聊天区不受影响） |
| C9 | 开关关闭 | 视频区不拦截右键（站点缺省行为不变） |

### 7.2 人工走查验收（合成事件无法覆盖的真实时序）

| # | 走查项 | 方法 | 通过标准 |
|---|-------|------|---------|
| W1 | 真实右键命中率 | 高/中/低三档弹幕密度下，对移动中弹幕真实右键各 ≥ 20 次 | 命中并弹出**正确目标**弹幕菜单的比例 ≥ 95%；未命中时无菜单无残留 |
| W2 | 冻结体验 | 右键后被点弹幕静止、其余照常滚动；菜单期间无闪烁跳动 | 目视确认，无"半静半动"混乱 |
| W3 | 恢复完整性 | 以收藏/Esc/点外部三种方式关闭菜单 | 每种方式后弹幕均恢复运动，连续操作 10 轮无永久卡死 |
| W4 | 全屏链路 | 进入视频全屏 → 右键出菜单 → 收藏 → Esc 关菜单（退出全屏为浏览器默认行为，见 FR-V05）→ 退出全屏后再次右键 | 全程菜单可见可用；退出后宿主归位、功能正常 |
| W5 | 空场景 | 直播结束/首屏无弹幕时右键视频区 | 无菜单、无报错、站点行为不变 |
| W6 | 开关 | 关闭开关后两处右键 | 聊天区与视频区均不拦截；重新开启后恢复 |
| W7 | 网页全屏/影院模式 | 菜单避让与可用性走查 | 菜单不出视口、可正常操作 |

> W1 的 95% 为验收门槛 [PM 判断]；若走查不达标，启用回退预案：右键坐标 + 邻近弹幕反查（按距离最近的可信弹幕项补位），并重新走查。
