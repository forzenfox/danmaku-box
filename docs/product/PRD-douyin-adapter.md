2. **选择器认知更新**：主 PRD FR-06「类名为纯哈希（无语义前缀）、依赖 `#chatroom` 稳定 ID 与 `data-e2e` 测试属性」的 2026-08 认知，更新为：站点存在成体系的 `webcast-chatroom___*` 语义类名（hi 级主干，条目/文本/表情/输入栏全覆盖），哈希类名仅存在于条目内层结构（昵称/内容区外层 SPAN），`data-e2e` 降为探测兜底（实测 28 个不同值）。`#chatroom` 锚点本次未实测覆盖，不列为依赖。
3. **飘屏路径裁决关闭**：主 PRD 开放问题 Q5「抖音飘屏弹幕路径是否纳入二期范围」→ 裁决**关闭**：抖音 PC 直播无独立飘屏弹幕层（登录/未登录两次会话均验证），`pauseDanmu`/`resumeDanmu` 适配为 no-op。

另：主 PRD FR-04「输入框未登录（抖音二期）」交互行（回填置灰 + 登录引导）继续适用，实现机制按本 PRD 更新。

## 1. 需求背景

### 1.1 需求来源

主 PRD 1.1 定义「一期适配斗鱼直播，二期扩展至抖音直播」，目标 G5 承诺「二期接入抖音时，不改弹幕库与分组的产品逻辑，仅新增站点适配」。2026-09-21 双会话实测补齐了抖音锚点字典，二期启动条件（可行性证据 + 选择器字典）已齐备。

### 1.2 用户痛点

主 PRD 1.2 的三个痛点在抖音侧同样成立且部分更甚：

- **好弹幕无处收藏（更甚）**：斗鱼至少有官方收藏（虽有限制），**抖音直播没有任何弹幕收藏能力**，用户完全只能手动复制到备忘录。[调研支持：主 PRD 竞品分析表]
- **常用弹幕每次重新输入**：抖音直播间活动口令（抽奖、上墙、福袋口令）节奏极快，跨斗鱼/抖音活动的观众在两个平台间无法复用已积累的弹幕资产。
- **跨平台资产割裂**：用户在斗鱼仓库里收藏的应援口号、整活文案，在抖音直播间无法调出使用，反之亦然。

### 1.3 现状与可行性裁决

**现状：接口齐备、实现空缺、证据充分。** 代码层已为抖音预留位置（`SiteAdapter.site` 类型含 `douyin`、`SiteDetector` 已实现 douyin 域名分支），但无 `douyin.ts` 适配器实现。2026-09-21 实测补齐了全部缺失证据：

| # | 验证项 | 实测结果（依据 selector-dict） | 对产品的意义 |
|---|--------|------------------------------|-------------|
| 1 | 聊天区锚点 | `.webcast-chatroom` 体系语义类全命中（条目/文本/表情/列表）；条目内层为哈希类，不硬编码即可 | 右键收藏链路可用 |
| 2 | 右键事件 | 登录/未登录两态 `contextmenu` 均 `prevented:false`，`target` 命中条目 | 自建菜单可挂载，收藏无需登录 |
| 3 | 输入框 | 已登录为 React 受控 `contenteditable`；未登录整体不渲染、被登录提示条替代 | 回填仅限已登录；未登录需引导 |
| 4 | 回填写入 | 直写+input 事件 React 不感知；execCommand/真实键盘感知 | 回填事件序列需独立验证（与斗鱼分叉） |
| 5 | 飘屏 | 视频区无任何弹幕层（两态一致） | 冻结/恢复降级 no-op |
| 6 | 列表形态 | 虚拟列表（窗口约 21 条、节点复用、`data-id` 随复用清空） | 需事件委托 + 弱化身份校验 |
| 7 | 直播间判定 | URL 首段纯数字，与斗鱼同范式 | `isLiveRoom` 直接复用 |

**可行性裁决：技术可行，收藏零门槛、回填限已登录。** 改动全部收敛在站点适配层（新增一个适配器模块 + 探测器装配），弹幕库、分组、收藏链路、菜单 UI 等通用层零改动，符合主 PRD G5。[实测支持：selector-dict 全表]

## 2. 需求目标与范围

### 2.1 目标

| # | 目标 | 衡量方式 |
|---|------|---------|
| GD1 | 抖音直播间内右键收藏可用，**登录/未登录均可**，全程 ≤ 100ms 弹出菜单 | 双登录态操作走查 + 性能验收 |
| GD2 | 收藏数据 100% 为单条弹幕文本，来源平台标记为 douyin | 自动化契约测试 |
| GD3 | 已登录回填可用；未登录回填明确置灰并提供登录引导，不阻塞弹幕库其余功能 | 双登录态走查 |
| GD4 | 通用层（弹幕库/分组/备份/菜单/消息链路）零改动接入抖音 | 迭代评审 + 斗鱼全量回归 |
| GD5 | 适配探针在登录/未登录两态均判定「适配存活」（输入框 ∨ 登录提示条） | 自动化契约测试 |
| GD6 | 抖音直播间改版导致适配失效时，明确降级提示而非静默 | 走查 |

### 2.2 范围

**做**：

- 抖音适配器实现：直播间判定、双态探针、登录态真实判定、聊天区弹幕命中与文本提取、已登录回填（React 受控事件序列）、无飘屏 no-op 降级；
- 未登录体验：收藏照常可用；回填引导登录（提示文案 + 入口）；
- 站点改版降级容错（继承主 PRD FR-06 两级降级原则）。

**不做**：

- **飘屏路径**：实测无此层，本次关闭（主 PRD Q5 裁决）；
- **协议层（WebSocket）收藏**：维持 DOM 路线，`webcast/im/push/v2` 仅作 DOM 路线整体失效时的未来备选，不在本期立项[主 PRD FR-06 预留备选]；
- **代登录、代发**：坚持「只回填不代发」产品原则（主 PRD 2.3），未登录引导跳站方登录入口，插件不触碰凭据；
- 斗鱼适配的任何改动（含飘屏专项成果），本期零触碰。

### 2.3 产品原则（继承与补充）

- **本地优先 / 只回填不代发 / 融入而非改造**（继承主 PRD 2.3）；
- **登录门槛最小化**（本 PRD 新增）：收藏是读取行为，不设登录门槛；仅写入（回填）依赖站方登录，由站方自身规则决定，插件只如实呈现状态并引导；
- **实时判定优先**（继承项目工程经验与飘屏专项 2.3）：登录态、锚点存活均以事件发生时刻的实时探测为准，不缓存过期快照、不做定时轮询。

## 3. 用户与使用场景

### 3.1 场景（按优先级）

**场景 D1：未登录随手收藏（最高优先级）**
用户以游客身份逛抖音直播间（抖音未登录可正常观看），看到一句好弹幕右键即可收藏入库。无登录弹墙，收藏链路与斗鱼体验一致。

**场景 D2：已登录活动应援回填**
主播发起冲榜活动，用户从弹幕库点击已收藏口号回填到抖音输入框，亲手发送。回填与斗鱼体验一致，仅发送动作属于用户。

**场景 D3：未登录回填引导**
未登录用户在弹幕库点击「回填」，按钮置灰并提示「登录后即可使用弹幕回填」，提供登录入口指引，弹幕库浏览、分组、备份不受影响。[主 PRD FR-04 既有定义延续]

**场景 D4：跨平台复用**
用户在斗鱼直播间收藏的梗弹幕，在抖音直播间直接调出回填/收藏；`platform=douyu/douyin` 字段记录来源，用户无感知平台差异。

### 3.2 用户故事

- 作为一名活动型观众，我希望在抖音直播间右键就能收藏弹幕，这样不用切去备忘录复制。
- 作为一名未登录的抖音游客，我希望收藏不被打断，这样我逛直播间时随手就能积累弹幕。
- 作为一名已登录的抖音用户，我希望点击收藏条目后弹幕落入抖音输入框，这样冲榜活动时能跟上节奏。
- 作为一名跨平台观众，我希望斗鱼收藏的口号在抖音也能用，这样我的弹幕资产跟着我走。
- 作为一名用户，我希望抖音页面改版时插件明确告诉我不适配了，这样我不会对着置灰按钮困惑。

## 4. 术语表（增量，基础术语见主 PRD 第 5 章）

| 术语 | 定义 |
|------|------|
| 语义类名 | 带语义前缀的 CSS 类名（如 `webcast-chatroom___item`），稳定可作锚点主干 |
| 哈希类名 | 无语义的随机构建类名（如 `Cl4EfhXg`），随前端构建易变，仅运行时探测 |
| 登录提示条 | 未登录时替代输入栏的 DOM 区域（`.cjR8oGui`），文本「需先登录，才能开始聊天」 |
| React 受控输入 | 输入框值由 React 状态驱动，需以站方可感知的事件序列写入（实测直写+input 事件不感知） |
| 虚拟列表窗口 | 聊天列表仅渲染可视窗口数量条目并复用节点（实测约 21 条），`data-id` 随复用清空 |
| execCommand 回填 | 以 `document.execCommand('insertText')` 写入内容使 React 感知的降级写入方式（实测有效） |

### 5.1 FR-D01 适配探测与登录态判定

#### 业务逻辑

进入抖音直播间后，适配器按三步完成探测与判定：

1. **直播间判定**：URL 首段为纯数字（`/^\d+$/`，如 `/492632285289`），与斗鱼同范式；首页/目录/用户页不挂载任何能力（继承主 PRD FR-06 与斗鱼适配既有行为）。
2. **双态探针（probe）**：必需锚点为「输入框 `[contenteditable=true]` **或** 登录提示条 `.cjR8oGui`」，二选一命中即适配存活；可选锚点为弹幕列表 `.webcast-chatroom___list`，缺失仅记录不判失效（与斗鱼「输入框为准」语义对齐，但必需锚点集合因登录态而放宽）。
3. **登录态判定（getLoginState）**：输入框存在 → `logged_in`；提示条 `.cjR8oGui` 存在 → `logged_out`。两态互斥（输入框与提示条不会同时渲染，实测确认），为回填可用性提供依据。

#### 交互逻辑

| 场景 | 系统响应 |
|------|---------|
| 进入直播间（任意登录态） | 探测通过，插件图标激活，右键收藏可用 |
| 直播间内完成登录 | 提示条消失、输入框渲染；回填即时恢复可用（实时判定，不刷新页面） |
| 直播间内退出登录 | 输入框消失、提示条出现；回填即时置灰引导（实时判定） |
| probe 必需锚点全部缺失 | 整站适配失效，状态条提示（见 FR-D05） |

#### 字段规则

| 字段 | 说明 |
|------|------|
| 必需锚点（探针） | `[contenteditable=true]` ∨ `.cjR8oGui`，二选一 |
| 可选锚点（探针） | `.webcast-chatroom___list` |
| 登录态信号 | 输入框存在 = logged_in；`.cjR8oGui` 存在 = logged_out |

#### 边界与异常

- **锚点复用风险**：`[contenteditable=true]` 为宽选择器，需限定在聊天区容器 `.webcast-chatroom` 内查询，避免命中页面其他可编辑区域（如搜索框等）。
- **登录态不缓存**：每次回填/交互前实时探测（事件驱动），禁止在页面生命周期内缓存登录态快照——直播间内登录/退出是站方支持的动态行为，缓存会制造误判（继承「状态快照时效性」工程教训）。
- **哈希类名不依赖**：条目内层结构类名（`Cl4EfhXg` 等）一律不硬编码。

### 5.2 FR-D02 聊天区右键收藏

#### 业务逻辑

用户在聊天区弹幕条目上右键，插件捕获条目并弹出既有「藏+」菜单，收藏链路完全复用（COLLECT_DANMAKU 消息、分组写入、toast 提示零改动）。**登录与未登录均可收藏**（两态 contextmenu 实测均未被站方拦截）。

#### 弹幕命中与提取规则（适配器契约）

| 能力 | 规则 | 依据 |
|------|------|------|
| 条目命中 | `target.closest('.webcast-chatroom___item')` | 实测 target 为条目内 SPAN，closest 可回退 |
| 空占位过滤 | 命中条目文本非空或含 `img/svg` 才算有效（虚拟列表有空占位节点） | 对齐斗鱼 FR-V02 语义 |
| 文本提取 | 先查 `.webcast-chatroom___content-with-emoji-text`，缺失回退条目 `textContent` | 文本/表情锚点互斥，先精确后宽泛 |
| 富内容判定 | 条目内含 `IMG` → `hasRichContent=true`，toast 注明「已忽略表情/图片」 | 对齐主 PRD FR-01 |
| 来源标记 | `platform=douyin`、`room=URL 首段房间号` | 对齐主 PRD FR-01 字段规则 |

#### 交互逻辑

| 用户动作 | 系统响应 |
|---------|---------|
| 右键弹幕条目（登录） | 弹出「藏+」菜单，流程与斗鱼一致 |
| 右键弹幕条目（未登录） | 同上，无登录弹墙，收藏正常写入 |
| 加入分组 / 收藏到新分组 / 复制文本 | 与斗鱼聊天区收藏完全一致（通用层复用） |
| 空文本条目 | 「复制弹幕文本」置灰，收藏可保存空文本条目（与主 PRD FR-01 一致） |

#### 边界与异常

- **虚拟列表节点复用**：条目 DOM 被站方回收复用（`data-id` 随复用清空），收藏内容一律以**事件发生时刻的事件目标**为准提取，禁止跨时刻持有条目引用；弹幕冻结身份校验（斗鱼飘屏的 uuid 三重校验）在抖音无稳定标识可用，本功能不涉及冻结，仅要求「右键瞬间完成提取」。[实测支持：selector-dict 虚拟列表风险项]
- **事件委托**：弹幕滚动容器高频增删节点，监听挂载在容器级（document/聊天区容器），不对复用条目挂监听。
- **纯表情弹幕**：可收藏（空文本 + 富内容标记），行为与主 PRD FR-01 一致。
- **iframe 嵌套**：弹幕若位于嵌套页面导致右键能力不可用时静默降级（继承主 PRD FR-01）。

### 5.3 FR-D03 弹幕回填

#### 业务逻辑

已登录用户从弹幕库点击条目（或其「回填」按钮），插件将文本写入当前活动标签页抖音直播间的输入框。**回填仅限已登录**：未登录时输入框不渲染（无写入目标），回填置灰并引导登录。

回填写入为 React 受控输入，实测警戒（selector-dict 输入框章节）：

| 写入方式 | 实测结果 | 结论 |
|----------|----------|------|
| 直写 `innerText` + `InputEvent('input')` | 文本进 DOM 但 React 不感知（发送按钮不出现） | **不可照搬斗鱼范式** |
| `execCommand('insertText')` | React 感知 | 可行兜底 |
| 真实键盘输入 | 完全感知 | 基准 |

最终事件序列在**实现阶段现场实测定稿**（候选：焦点 + 全选清空 + execCommand 写入；或「原生 setter + 双事件派发」组合再验证），以「写入后站方发送按钮出现」为验收口径。写入后聚焦输入框并置光标于末尾（继承主 PRD FR-04）。

#### 交互逻辑

| 用户动作 | 系统响应 |
|---------|---------|
| 已登录点击条目 | 回填到抖音输入框，toast「已回填，可直接发送」，输入框聚焦 |
| 未登录点击条目 | 「回填」置灰，悬停提示「登录后即可使用弹幕回填」，提供登录入口指引；弹幕库其余功能不受影响 |
| 连续点击多条 | 后一次覆盖前一次（替换模式，与主 PRD FR-04 一致） |
| 回填超长弹幕 | 填入至平台上限并 toast「内容超出平台字数限制，已截断」（上限待实测，见开放问题 Q-D1） |
| 空文本条目回填 | 置灰，提示「该弹幕无文本内容，无法回填」（与主 PRD FR-04 一致） |
| 当前页非直播间/站点改版 | 置灰并给出原因（继承主 PRD FR-04 边界） |

#### 边界与异常

- **未登录中途退出**：直播间内退出登录后输入框消失，回填实时探测返回 `logged_out`，置灰引导（配合 FR-D01 实时判定）。
- **写入未感知兜底**：若事件序列写入后站方未感知（发送按钮未出现），视为回填失败并 toast「回填未生效，请手动粘贴（已复制到剪贴板）」——复制文本兜底始终可用。
- **不代发**：插件只写入，发送始终由用户完成（主 PRD 2.3 原则，账号安全红线）。

### 5.4 FR-D04 飘屏与冻结降级

#### 业务逻辑

抖音 PC 直播无独立飘屏弹幕层（登录/未登录两态均实测确认），因此：

- `pauseDanmu` / `resumeDanmu` 实现为 no-op（无参调用与带参调用均不动作）；
- 右键「暂停—操作—恢复」链路在抖音退化为「直接弹菜单」，无冻结环节；
- 冻结相关的身份校验逻辑（uuid/复用防护）不引入抖音适配器。

#### 边界与异常

- **未来再评估**：若抖音后续版本引入视频区弹幕层，本模块按实测重新立项（不自动启用），当时以新一次实测证据为准。

### 5.5 FR-D05 降级容错

#### 业务逻辑

- **整站适配失效**（必需锚点全部缺失，如站点改版移除聊天区）：弹幕库面板显示「抖音适配暂不可用」状态条，回填置灰 + 复制文本兜底，不静默（继承主 PRD FR-06 两级降级原则）。
- **局部能力缺失**（如弹幕位于 iframe 导致右键不可用、写入选入未感知）：该能力入口置灰或静默跳过，不打扰观看。
- **登录态切换**：实时判定（FR-D01），无快照、无轮询。
- **适配恢复**：插件更新后状态条自动消失，无需用户操作。

#### 边界与异常

- **辅助探测兜底**：`data-e2e` 属性体系（实测 28 个不同值，含 `live-chatting`、`danmaku-setting-icon` 等）仅作运行时特征探测兜底，不作核心锚点——属站方内部约定，随版本可能变更。[selector-dict]
- **弹幕量低不误判**：媒体类直播间弹幕被限流、条目稀少属正常现象，不得作为适配失效依据（已隔离验证与登录无关联）。[selector-dict 风险项 4]
