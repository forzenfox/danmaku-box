# 抽屉 UI 优化 V2：非全高布局 + 接口精简 + 回填自动收起

- 日期：2026-08-31
- 状态：已评审（脑暴 + 实测定位），待实现
- 关联文档：2026-08-31-drawer-ui-design.md（V1 抽屉）、2026-08-31-drawer-ui.md（V1 实现计划）、技术方案 V0.2

## 1. 背景与问题

V1 抽屉（覆盖式、iframe 复用 panel.html）已上线手动验证通过，但存在三点体验问题：

1. **纯白全高面板遮挡输入区**：回填弹幕后需要在右侧聊天区底部输入框核对内容，但全高抽屉（top:0;bottom:0）正好盖住输入框，必须手动关闭才能发送。
2. **行内按钮过密**：每条弹幕行内 4 个按钮 [回填][移动][编辑][删除]，横向占位过大，窄抽屉下列表信息被挤压。
3. **宽度固定**：固定 720px，窄屏/网页全屏下可能遮挡直播视频区域。

## 2. 决策记录（评审裁决）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 抽屉**非全高**：top:0 对齐、height: min(62vh, 560px) | 弹幕输入框实测位于视口底部约 94vh（见 §4），62vh 高度底部留白 ≥32vh，输入框始终可见可点 |
| 2 | 宽度响应式 + 视频保底：width: min(720px, 40vw) | 不遮挡视频区（保底 60% 视口宽），窄屏/F11 自适应 |
| 3 | 行内按钮精简为 [回填][编辑]；[移动][删除] 移至底部批量栏 | 高频操作留行内；低频操作并入已有批量模式，批量勾选单条即等价单条操作，不占用常态空间 |
| 4 | 回填成功后抽屉**自动收起**（延迟 ~0.9s，留 toast 反馈） | 用户回填后需立即看到输入框内容完成发送；收起后输入框露出（content script 已聚焦输入框） |
| 5 | 网页全屏 F11 **不监听**；播放器全屏（fullscreenchange）仍自动收起（V1 保留） | F11 不触发 fullscreenchange；F11 下非全高 + 底部留白天然适配，无需事件处理 |
| 6 | 收起逻辑于 content script 本地闭环（drawer.hide()），**不加消息协议、SW 零改动** | 回填由 content script 执行器完成（FILL_ACTION），与 drawer-host 同上下文，直接调用即可 |

## 3. 目标布局

```
┌─ 视口（F11 / 窗口通用）────────────────────────────────────┐
│ 直播画面区域                                            │
│                                ┌────────────────────┐  │
│                                │ 弹幕收藏夹          │  │ ← 抽屉 top:0
│                                │ 高度 <= min(62vh,560)│  │    right:0
│                                │ 分组|列表           │  │
│                                │ [行内按钮(常态)]     │  │
│                                └────────────────────┘  │
│                     〔底部留白 >= 32vh〕                │
│  ┌───────────────────────────┐                          │
│  │ 弹幕输入框（~94vh，实测）   │  ← 完全不被遮挡         │
│  └───────────────────────────┘                          │
└──────────────────────────────────────────────────────────┘
```

## 4. 实测数据（本机 douyu，2026-08-31 浏览器实测）

| 检测项 | 结果 |
|---|---|
| 弹幕输入框（.ChatSend-txt） | x=1556, y=894, w=236, h=42，bottom=936 |
| 输入框距视口底 | 13px ≈ 底部 2%（即 y≈94vh） |
| 输入框距右缘 | 72px（位于右侧聊天区内） |
| F11 判定 | fullscreenElement=null、outer-inner=56px（当前窗口态；F11 下视口整体扩大，输入框仍贴底同比例） |

**参数推导**：抽屉 height=62vh 时 bottom≈62vh < 输入框顶部 94vh，留白 32vh。F11 下视口变高，二者同比例下移，留白仍成立 => 一次适配两种模式。

## 5. 变更清单

### 5.1 布局参数（drawer-host.ts 内嵌样式）

css .drawer-host 改动：

- position: fixed; top: 0; bottom: auto（非全高）
- height: min(62vh, 560px)
- width: min(720px, 40vw); max-width: 720px
- background: #fff；transform/过渡/open 态保留
- 把手位置随容器 top 对齐（维持 right:0; top:45% 亦可）
- 宽度拖拽 + storage.session 记忆保留（V1 规划项，本次实现）

### 5.2 行内按钮精简（panel.ts / panel.css）

- 常态行内：回填 + 编辑（非批量模式且非删除确认态）
- 批量模式：行内显示勾选 + 内容，隐藏移动/删除按钮；底部批量栏「已选 N 条 / 移动 / 删除 / 退出批量」（batch-bar 已存在，复用）
- panel.ts renderItem()：移除常态「移动/删除」按钮分支，批量模式只渲染勾选与内容
- 空内容弹幕仍禁用「回填」（现状保留）

### 5.3 回填自动收起（content script 本地闭环）

- drawer-host.ts 新增公开方法 hide(): void => applyOpen(false) + persist()（会话记忆写回关闭态）
- content/index.ts FILL_ACTION 处理器：handleFillAction 返回 ok 后 setTimeout(() => drawer.hide(), 900)（延迟让抽屉内 toast「已回填」可见）
- 输入框聚焦由现有 fill-engine 完成 => 收起后可直接发送
- 不改：消息协议（无新消息）、service worker、panel.ts 数据流

### 5.4 明确不改

- 播放器全屏收起逻辑（V1 onFullscreen 保留）
- SW / 消息协议 / 设置页 / 备份
- 不为 F11 增加任何监听（布局自适应覆盖）

## 8. 明确不做（YAGNI）

- 不做 F11 事件监听
- 不做抽屉内嵌输入框/发送能力（输入必在直播间原生通道完成，见 V1 决策）
- 不做主题切换、动画定制（沿用现有 CSS）
