# 抽屉 UI 优化 V3：分组水平化 + 行内按钮精简

* 日期：2026-09-02

* 状态：**设计已确认**（2026-09-02 视觉伴侣走查，用户全选并确认整体终态，待实现）

* 关联文档：2026-08-31-drawer-ui-v2-design.md（V2 抽屉）、技术方案 V0.2、PRD.md、prototype-design.md

## 1. 背景与问题

V2 抽屉（非全高 + 行内两按钮 + 回填自动收起）已验收，但窄容器（Chrome 侧边栏 / 抽屉 iframe，实测宽约 340px）下仍有三点体验问题：

1. **左侧 150px 纵向分组栏挤压列表**：窄容器中约占一半宽度，列表实际可用宽度仅约 190px；分组多时分组栏自身纵向滚动。
2. **行内「回填」按钮功能重复**：单击条目内容已是回填（V2 契约），「回填」按钮冗余，双入口增加认知负担且占用行内空间。
3. **「编辑」文字按钮占位大**：行内按钮均为文字形态，压缩内容显示宽度；空内容弹幕（无文本，无法回填）点击仅弹 toast，操作无意义。

## 2. 决策记录（评审裁决）

| # | 决策 | 理由 |
| - | --- | --- |
| 1 | 分组**水平化为顶部单行横向 chip**，超出视口水平滚动 + 拖拽查看 | 横向宽度是窄容器最稀缺资源；列表可用宽 ~190px → ~340px；溢出用滚动/拖拽解决，与用户原始诉求一致 |
| 2 | 移除行内「回填」按钮 | 单击内容 = 回填（V2 契约 resolveContentClick），按钮冗余；移除后行内无常驻按钮 |
| 3 | 「编辑」文字按钮 → **铅笔图标**，行 hover / 键盘聚焦时浮现 | 行内常态零操作最干净；图标 + title + aria-label 保证可发现与可达 |
| 4 | 空内容弹幕（`［纯表情弹幕］`）**点击直接进入编辑态** | 回填无意义，点击转编辑最高效（替代原 toast 提示） |
| 5 | 分组管理入口保留：hover chip 尾部浮现 ⋮（重命名/删除） | 沿用现有 `nav-more` 菜单交互，行为不变，仅呈现位置随 chip 移动 |
| 6 | 批量交互、回填自动收起、播放器全屏收起、F11 不监听等 V2 行为**保持不变** | 本次仅触及布局与行内呈现，不涉数据流与消息协议 |

## 4. 实测上下文（窄容器宽度依据）

* Chrome `side_panel` 与直播间抽屉 iframe 共用 `panel.html`，实测内容宽约 340px（V2 收窄至 min(340px,22vw) 后）。
* 当前列表容器：`panel-main` 内 `group-nav` 固定 150px + `list-container` flex:1 ⇒ 列表宽 ≈ 容器 − 150px − 边框。

## 5. 变更清单

### 5.1 分组导航水平化（panel.ts renderNav 重写 + panel.css）

* `.group-nav`：由 `width:150px; overflow-y:auto` 改为 **100% 宽、单行、`overflow-x:auto`**（横向滚动容器，保留触摸屏原生平移）。
* `.nav-item`：由块级行改为 **胶囊 chip**（圆角 `--radius-full`、1px 边框、hover 底色；激活态蓝色底 `--bg-active` + 主色文字）。
* 顺序：`全部弹幕`（置顶、不计入横滚总数）→ 各分组 → 末尾固定 `＋ 新建分组` chip（`nav-new-group` 迁移为 chip 形态）。
* 分组操作：chip hover 尾部浮现 ⋮（复用 `nav-more` 及 `showGroupMenu`/`closeGroupMenu`，仅样式适配）。
* 桌面端横滚手感：实现**拖拽平移**（pointerdown/pointermove/pointerup，`cursor: grab/grabbing`）；保留原生 `overflow-x:auto` 作为兜底（触屏/滚轮 shift+wheel）。
* 可测性：将「全部置顶、新建分组置尾、激活判定、计数汇总」逻辑抽为纯函数（如 `buildNavItems(groups, selectedGroupId)`），node:test 单测；chip DOM/拖拽走人工走查。
* 列表容器由 150px 精简补偿：移除左栏占位后列表默认占满，微调 padding 即可，无需结构性改动。

### 5.2 行内条目精简（panel.ts renderItem + panel.css）

* **移除**：`回填` 按钮创建分支（`fill` 按钮及其 disabled/title 状态逻辑删除；`state.siteStatus` 在 renderItem 的唯一用途即按钮置灰，随按钮一并移除，非直播间/适配失效提示由 `fillDanmaku` 的 SITE_UNSUPPORTED / ADAPTER_DOWN toast 兜底；单击内容回填、空内容点击新语义见下）。
* **编辑图标化**：`编辑` 文字按钮 → 铅笔图标按钮（内联 SVG，`title="编辑"` + `aria-label="编辑"`）；默认 `visibility:hidden`，行 `:hover` 或 `:focus-within`（键盘可达）时 `visibility:visible`。
* **空内容条目**：点击内容不再走 `fillDanmaku`（原 toast 提示），改为 `state.editingId = item.id; renderList()` 直接进入编辑态；图标同位置浮现。
* `resolveContentClick` / `toggleChecked`（list-interaction.ts）**契约不变**：非批量单击内容 = 回填；批量单击 = 切换勾选。
* 批量模式行内仍不渲染任何操作（现状保留）。

### 5.3 无障碍与细节

* 图标按钮：`title` + `aria-label` 齐全；键盘 Tab 聚焦即显示（不依赖 hover only）。
* 拖拽平移期间抑制文本选中（`user-select:none`）；拖拽与点击（chip 切换分组）通过移动阈值区分，避免误触。
* 分组 chip 语义沿用现有 `div + click`（不做大改），走查关注键盘操作路径。

### 5.4 明确不改

* 抽屉布局参数：`top:0; height:min(62vh,560px); width:min(340px,22vw)`（V2 验收值）。
* 回填自动收起（0.9s）、播放器全屏收起、F11 不监听（V2 行为）。
* 搜索 / 排序 / 分页 / toast / 模态 / footer / 批量交互 / 回填引擎与消息协议 / SW / 设置页 / 备份。
* 不新增消息协议，不新增权限。

## 8. 明确不做（YAGNI）

* 不引入图标库/字体：使用内联 SVG 铅笔，无新增依赖。
* 不做分组拖拽排序、分组置顶/固定、分组云换行模式（与决策 1 的"单行横滚"互斥，避免再次出现两种布局）。
* 不做可折叠分组区、分组搜索。
* 不做主题切换、动画定制（沿用现有 CSS 变量体系）。
